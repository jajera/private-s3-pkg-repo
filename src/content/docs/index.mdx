## Why this lab

You want the same private **yum and apt trees** in Sydney and Auckland — packages
plus `repodata` / `dists`, not plain objects. A full
[Pulp](https://pulpproject.org/) stack can host those repos, but you own the
servers, upgrades, and network path. Here S3 holds the rpm and deb layout, a
Lambda rebuilds indexes after publish, and each consumer VPC reads its
**local** bucket through a
<Tooltip term="gateway-vpce" label="gateway VPC endpoint" />.

A separate public <Tooltip term="catalog-ui" label="catalog viewer" /> lists
what was published. It is read-only metadata (`catalog.json`), not a package
download CDN and not Pulp’s UI.

Once packages and indexes have replicated, Auckland keeps serving Auckland if
Sydney is down (and the other way around). That is not full multi-Region
<Tooltip term="ha" label="HA" />. You still publish to Sydney, replication is
async so <Tooltip term="rpo" label="RPO" /> is not zero, and anything in a failed
Region is still down.

## What you will do

Everything goes through `./scripts/demo.sh`.

<CardGrid>
  <Card title="Shared buckets + CRR" icon="rocket">

  </Card>
  <Card title="Dual-OS consumers" icon="seti:folder">
    AL2023 + Ubuntu 24.04 probes per Region, each VPC locked with
    <Tooltip term="source-vpce" label="aws:SourceVpce" />.
  </Card>
  <Card title="Publish + rebuild" icon="approve-check">
    Put sample rpm/deb under <code>repos/</code>, then Lambda indexes
    (<Tooltip term="createrepo" label="createrepo_c" /> / apt-ftparchive) and
    <code>catalog.json</code>.
  </Card>
  <Card title="Prove dnf / apt" icon="seti:shell">
    SSM Run Command installs the samples on both OS probes in Syd and Akl.
  </Card>
</CardGrid>

| Expectation | Notes |
| ----------- | ----- |
| Same package keys | Different regional hostnames |
| Cross-region installs | Via the replica tree, not cross-Region PrivateLink |
| Catalog viewer | Public website; packages stay private |
| Cost while running | S3 + CRR + Lambda/ECR + 4 probe EC2 + SSM endpoints |

<Aside type="caution">
  This lab costs money until you tear it down. Destroy consumers before you
  empty the shared buckets if you created SSM interface endpoints.
</Aside>

## Out of scope

- Full Pulp (or other long-lived repo servers)
- Public package download from the catalog viewer
- CodeBuild / schedule-first index rebuild
